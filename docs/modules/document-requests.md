# Document Requests — module rules

This file holds the rules and current state of the Document Requests module, moved out of `CLAUDE.md` on 13 Oct 2026, verbatim. **It is NOT loaded automatically, and it MUST be read before changing this module.**

## Document Requests

- Agreed workflow: resident submits → Secretary approves/rejects → payment (record/verify) → release. The Punong Barangay only views/signs.
- Status lifecycle — canonical lowercase values defined in `backend/src/constants/requestStatus.js` (single source of truth; later stages must not invent new strings): `pending` (resident submitted) → `approved` / `rejected` (Secretary review) → `ready_for_release` (payment verified + signed) → `claimed` (released, `claimed_at` set). `cancelled` = withdrawn by the resident.
- Implemented: Stage 1 document-type management; Stage 2 resident submit (`POST /api/document-requests`, requires a linked resident record) and tracking (`GET /api/document-requests/mine[/:id]` — filtered by `requested_by_user_id`, so users only ever see their own). Resident screens: `/resident` (My Requests) and `/resident/request`. Migration 005 added `requested_at`.
- Stage 3 Secretary processing: `GET /api/document-requests[?status=…]` (list across residents) and `GET /:id` (detail incl. the resident record for verification) — **these two GETs now also admit `punong_barangay` and `staff`** (`177dabd`); `POST /:id/approve|reject` stays **Secretary-only**; only `pending` may be decided, reject requires a reason (migration 006 added `rejection_reason` + `processed_at`). Screens: `/secretary/requests` (manage), `/staff/requests` and `/punong-barangay/requests` (view-only). A **Staff** caller receives a narrowed resident embed and no requester email — see `docs/brgyserve-implementation-log.md` → **"Read-only access for Staff and the Punong Barangay"**, which is the one place that decision is written down. Rejection reason is shown to the resident in My Requests.
- Resident cancel: `POST /api/document-requests/mine/:id/cancel` — own requests only (404 otherwise), only from `pending` (409 otherwise) → status `cancelled`. Cancel button on pending rows in My Requests. No edit — residents cancel and resubmit.
- **A PAID PHP 0 charge reads "No fee", and a billed request shows the fee it was charged** (`367229f`). Approval creates a PHP 0 document charge already PAID with no payment row, and a booking does the same for a PHP 0 rental. My requests, My rentals and the request detail say "No fee" for it through `isNoFeeCharge()` (`utils/chargeMethod.js`), which **reuses `isZeroFee()` — never write a second zero test**, because `Number()` reads null and `""` as 0. An UNPAID or VOID PHP 0 charge keeps its "Amount due" wording. **Once a request is billed, its Fee is the charge's amount, never the document type's fee**: a type's fee can change after approval (request 11's type costs PHP 20.00 now; its charge is PHP 0). Tested by `test:auth` section T.
- **The shared list is seven status tabs over ONE load** (`e3ce48a`). `SecretaryRequestsPage` (Secretary, Staff, Punong Barangay) sends `GET /api/document-requests?status=all` once and filters in the browser: Pending, Approved, Ready for release, Claimed, Rejected, Cancelled, All, each with its count over the whole list, so the counts read the same on every tab. The page opens on Pending, as the select it replaced did, and the heading names the tab ("6 pending requests", "77 requests" on All). Refresh, Try again, Back after a request was acted on and a filed walk-in load the list again exactly when they did before, and keep the chosen tab.
  - **A tab must never send a request.** `load` depends on `authFetch` alone; putting the tab back into its dependencies reloads on every press, and `test:auth` section W fails it. The backend's `?status=` filter is unchanged; the page simply no longer asks per status.
  - **The tab order is set in `utils/requestList.js`, never taken from `STATUS_META`'s key order**, which puts Rejected before Ready for release.
  - **On a phone the heading has a line of its own** (`.doc-requests-head h2 { flex-basis: 100% }`, inside the ISSUE 7 640px block of `index.css`). Its length changes with the tab, and where it sometimes fitted beside Refresh and Encode walk-in, pressing a tab moved the strip 32px (measured at 360 to 414 for the Secretary, 320 for Staff).
- **The list has a search box** (`e5aa090`), in a row of its own under the heading and Refresh and over the tabs: `components/ListToolbar.jsx`, the Payments box (see "The Payments page"). It filters the loaded list as you type and the tabs split what matches: their counts follow the search, the chosen tab stays, and the heading reads "2 of 6 pending requests match", in a polite live region. The search lives through every reload and Back from a request, and nowhere in the browser.
  - **A search reads ONLY what a row shows of who and what**: `searchParts()` in `utils/requestList.js`, which is the name as the row shows it (`requesterName`), the @account where the row shows one (`accountHandle`, which the row's account note calls too) and the document type. **Never the purpose, the rejection reason, an email, a status word, a walk-in's filer or the request number.** The trap is Staff's payload: it has no resident `account`, but it still carries `requester.username`, which on a self-service request IS the resident's account, so reading it would let Staff find an account their rows never show. `test:auth` section X fails both. A column added to the row (the request number, next) joins `searchParts` in the same change.
  - **A keystroke or a page change must never send a request**, any more than a tab press may.
  - **Unlike Payments' box, this one is not drawn while the list loads or after a load fails**: it sits with the tabs under the row that holds Refresh, so a reload leaves Refresh where it was.
  - **Open, not fixed:** at 320px on Ready for release, a search makes the heading two lines ("1 of 4 ready for release requests matches" is 323px against 288), so the search row and the strip move down 22px on the first keystroke. From 360 up nothing moves with today's counts. The Secretary's placeholder is cut at 320, as Payments' is.
- **The list has a pager** (`eede21f`) under the rows, from 11 matches: `components/ListPager.jsx`, the Payments pager. Only the rows drawn are a page: the heading and the tab counts count every match, and the search runs before paging. A tab, search or Rows per page change goes back to page 1; Rows per page lasts the visit. Refresh, Try again and Back keep the page, and a list that shrank lands on its last page (Payments' clamp in render, skipped while loading).
  - **Open, not fixed:** above 640px the table sizes its columns to the rows drawn, so a page change moves them, by up to 106px on All (a tab change already moved them up to 74px). Pinning them would change the row layout.
